# Cape Town Rooftop Solar and Electricity Consumption
## Data Preparation Pipeline

### Overview

This directory contains the Python scripts and execution records used to
construct the household-month electricity consumption panel for the
Cape Town rooftop solar analysis.

The pipeline combines:
- Monthly prepaid and postpaid electricity consumption records.
- Electricity contract and geographic location information.
- Building footprint data.
- Rooftop solar (SHS/PV) detections derived from aerial imagery.
- Official SSEG registration records.
- Load-shedding block assignments and monthly load-shedding exposure.

The final outputs are separate prepaid and postpaid household-month
panels used in the subsequent econometric analysis.

Scripts are numbered in processing order. Letter suffixes indicate
multiple operations within a processing stage.

Execution records are retained alongside the scripts where available.
Execution dates refer to the original processing runs, not the date
the files were archived.

## 2. Final Analysis Dataset

The final formatted datasets are used in the subsequent
econometric analysis.

Prepaid and postpaid data are retained separately.

The final analysis panels apply a restriction based on
the number of electricity contracts associated with
each building, retaining buildings with no more than
five contracts.

The final panel is used for:
- Household fixed-effects regressions.
- Event-study analyses of rooftop PV adoption.
- Load-shedding exposure analyses.
- PV capacity heterogeneity analyses.
- Robustness and misclassification sensitivity analyses.

## 3. Reproducibility and Provenance Notes

The following limitations should be considered when
reproducing the pipeline.

1. **Prepaid execution:** The July 31 execution successfully
   wrote the final dataset but subsequently encountered a
   diagnostic error involving the missing `days_between`
   column. The data-generation stage completed before
   the error.

2. **Postpaid execution:** The July 29 output is readable
   and consistent with the archived script. A corresponding
   July execution log was not located.

3. **Location import:** The Step 2a script and resulting
   dataset have matching column structures, but no execution
   log was located. The configured output path differs
   from the path used downstream.

4. **Contract-location merge:** The August 1 execution log
   reports the April output directory, while Step 3 consumes
   the August 3 directory. Row counts match, but exact
   file equivalence was not verified.

5. **External inputs:** Several upstream inputs are stored
   outside this archive, including electricity transaction
   files, contract location CSVs, building footprints,
   aerial imagery prediction files, registration data,
   load-shedding schedules, and block boundaries.

6. **Execution records:** Logs document the reported
   execution results and QA checks. Their presence does
   not imply that every upstream input is included in
   this directory.

7. **Paths:** Current scripts use centralized paths in
   `paths.py`. Historical paths below document original
   execution provenance rather than current configuration.

8. **Archive filenames:** Script filenames have been
   standardized for readability. Original data-generation
   logic is unchanged by these filename changes.
